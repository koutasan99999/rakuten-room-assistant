# サングラスくまの表紙画像の自動生成：調査と実装計画（2026-11-14）

状態：調査・設計のみ（2026-11-14 改定：社長がデザインの参考資料・衣装の方針・予算を決定）。画像生成APIの実呼び出し・課金・PR・デプロイはまだしない。
目標：AI社員が選んだ商品を、固定キャラクター「サングラスくま」（衣装は場面に合わせて変える）が日常の中で使っている立体感のある3D調の画像を自動で作る。その画像に、タイトル文字をプログラムで重ねて、Instagramの表紙にする。社長が承認するまで外に出さない。

## 1. 全体の流れ（推奨案）

制作ラインで監査AIに合格した投稿セットに、表紙の画像を1枚ずつ付けます。

1. **マスター画像の確認（コード・0円）**：承認済みのマスター画像が登録されていなければ、ここで止まります（3章）。「マスター未登録」と表示し、別のクマでは代用しません。参考資料のコラージュもマスターの代わりにしません。
2. **場面の企画（文章のAI・約0.5円）**：主役の商品（本命）1点について、日常の場面を1つ決めます。場所・時間帯・くまの動作・**衣装**・商品の使い方を決めます（衣装は場面と商品の用途に合わせる。例：ジムならトレーニングウェア、キャンプならアウトドアの服。白衣・紺スクラブは医療・仕事の場面のときだけ）。
   - 商品の使い方は、商品データ（商品名・説明）にある用途だけにします。データから分からないときは「手に持って眺める」「机に置いてある」のような無難な場面にします。
   - 前の20件の場面（場所・動作・衣装）と重ならないように、これまでの場面を渡します。重複はコードでも確かめます。
3. **画像の生成（画像のAI・約8〜15円・推測）**：OpenAI の画像編集API に、マスター画像（1〜2枚）と商品写真（1枚）を参考として渡します。
   - キャラクターの決まり（固定要素）は毎回同じ文章で書きます：茶色〜キャメル色のふわふわしたくま／大きな黒いサングラス／丸い顔・小さな鼻・短い手足／ぬいぐるみのような立体的な3Dの質感／かわいくデフォルメされた体型。顔・体型・毛の質感はマスターと同じにします。衣装は場面の企画どおりにします。
   - 「立体感のある3DCGの質感・自然な光・浅い被写界深度」と指示します。特定の作品・会社の作風の名前は使いません。
   - 画像に文字・ロゴ・透かしを描かせません。商品の形・色は参考写真のとおりにします。
   - 1024×1536（縦長）、品質 medium。
4. **画像の客観確認（画像を読めるAI・約1円＋コード）**：はい／いいえで答えさせ、コードが判定します。
   - 固定要素がそろっているか（キャメル色のふわふわ・大きな黒いサングラス・丸い顔と小さな鼻・短い手足・3Dの質感）。顔と体型がマスターに近いか。平面的なイラストや別のくまになっていないか。衣装が場面の企画どおりか。
   - 商品が写っていて、参考写真と形・色が大きく違わないか。
   - 文字・ロゴ・透かしが無いか（参考資料には他社のロゴ入りの服・帽子があるが、生成画像では描かない）。手や指が崩れていないか。3D調か。
   - コードでは、画像の大きさと、壊れたファイルでないかを確かめます。
   - 不合格なら1回だけ作り直します。2回目も不合格なら、理由を残して「画像なし」にします（今までの表紙を使う）。
5. **保存（0円）**：画像（JPEG）をサーバーの保存場所に置きます（`media:{推測できない長いID}`）。投稿セットには、画像のID・場面・確認の結果・費用・モデル名を記録し、状態を「社長の確認待ち」にします。既存のデータは消しません。
6. **アプリで表示・承認（0円）**：投稿セットの画面で、生成した画像に、タイトル・小さな「AI生成イメージ」の表記・PR表記をプログラムで重ねて表紙を描きます（新しい表紙の型 `kuma_scene`）。
   - 社長は「承認」「作り直す（費用がかかる。上限内のときだけ押せる）」「使わない（今までの表紙）」から選べます。
   - 承認するまで、この画像は投稿に使われません。投稿そのものは段階2の公開の仕組みでも社長の承認が要るので、外には出ません。


## 3. マスター画像の登録（設計）

### 参考資料とマスターの違い
- **参考資料**（`assets/kuma-reference/`）：キャラクターの基準を人とAIが確かめるためのもの。今の15場面のコラージュはここに置いた。画像生成の参考画像としては渡さない（複数の場面が入っていると、生成画像も分割されたり、別の場面が混ざったりする恐れがある＝推測）。
- **マスター画像**（`assets/kuma-master/`）：画像生成のたびに参考として渡す、くま1体だけが写った高品質な画像。社長が承認したものだけ。

### マスター画像の条件（コードで確かめる）
- くまが1体だけ。コラージュや複数の場面ではない（形式の確認に加えて、客観確認のAIに「キャラクターは1体か」を聞く。費用約1円は登録のとき1回だけ）。
- 長い辺が1024ピクセル以上。PNG または JPEG。1枚10MB以下。
- 背景は無地かシンプル（背景の物が毎回の画像に写り込まないように）。
- 文字・ロゴ・透かしが無い。
- 種類：`front`（正面・上半身）は必須。`full`（全身・立ち姿）は推奨。`side`（斜め）は任意。最大3枚（参考画像が増えるほど費用が増えるため）。
- 衣装：無地の服か、何も着ていない状態を推奨（マスターの衣装が毎回の画像に残りやすいため＝推測）。

### 登録の手順
1. 社長が画像を用意する（作り方は下）。
2. 私（開発）が `assets/kuma-master/` に置き、`manifest.json` に記録する：ファイル名・種類（front/full/side）・大きさ・ハッシュ値（中身の指紋。差し替えを検出する）・登録日・状態（`pending`＝確認待ち）。
3. アプリの「表紙画像」の設定欄にマスターを並べて表示し、社長が「承認」を押す。承認日と「社長が承認」を記録して、状態を `approved` にする。
4. 画像生成は、`approved` のマスターがあり、ファイルのハッシュ値が記録と一致するときだけ動く。差し替えられていたら止める。

### マスターが無い間
- 場面の企画も画像の生成も動かない（費用0円）。仕事探しの記録に「マスター未登録のため、表紙画像は作らない」と出す。
- 表紙は今までのテンプレートのまま。

### マスター画像の作り方（社長が選ぶ。いずれも、この計画の承認とは別に費用の承認が要る）
- A：元の画像を作ったツールで、同じくまを1体だけ・無地の背景・正面と全身で作り直す（OpenAIの費用はかからない。ツール側の費用は社長の契約による）。
- B：このアプリで、コラージュの中の1場面を参考に、マスターの候補を数枚作る（画像生成APIを使う。1枚約10〜18円・推測。候補3枚で約50円まで）。候補は社長が選び、選ばなかったものは使わない。

## 4. 料金と予算の上限

### 料金（OpenAI の公式ページは、この環境のネットワークから開けなかった＝【要確認】）
複数の第三者の資料が、同じ数字を載せていました（gpt-image-2・1024×1536・出力だけ・1枚あたり）。

| 品質 | 1枚あたり（出力） | 円（1ドル155円で換算） |
|---|---|---|
| low | $0.005 | 約0.8円 |
| medium | $0.041 | 約6.4円 |
| high | $0.165 | 約26円 |

- 参考画像（入力）は別料金です。画像の入力は100万トークンあたり $8 とされ、参考画像1枚は大きさによって約1,000〜3,000トークン（推測）。参考画像3枚で約 $0.02〜0.07（約3〜11円）。
- gpt-image-2 は参考画像を常に高い忠実度で読むとされ、編集の使い方では基本料金の2〜3倍になるという資料もあります。
- **見積もり（推奨の設定：medium・参考画像3枚）：1枚 約10〜18円。** これに客観確認 約1円、場面の企画 約0.5円が加わります。作り直しが1回あると、1セットで最大 約40円。
- 今のコードの目安の表（`lib/tryon.js`）も、gpt-image-2・medium を12円としていて、ほぼ合っています。

### 予算の上限（2026-11-14 社長の決定：月200円・1日2枚で設計）
- 月の上限1,000円（全体）は変えません。画像の費用もこの中に数えます。
- 画像専用の月の上限：`IMAGE_MONTHLY_YEN`＝200円（月1,000円を超える値にはできない）。
- 1日の画像の上限：2枚（作り直し・マスター候補の生成を含む）。
- 1回呼ぶ前に、20円を見込み額として予算を確認します（`lib/budget.js` の check）。足りなければ呼びません。
- 自律運営の1日25円（文章のAI）とは分けて数えます。画像1枚で文章の仕事が止まらないようにするためです。
- 費用は、実際に使ったトークン数が返ってくればそれで計算し、返ってこなければ見積もりの値で記録します。どちらで数えたかを残します。
- 月200円では、約10〜15枚になります（推測）。毎日1枚作るには、月300〜500円程度が要る見込みです。

## 5. 技術的な注意（要確認）

- **実行時間**：今は1回60秒まで。画像の生成は medium で30〜90秒かかることがあります（推測）。
  - 推奨：Vercel の Hobby プランで、この関数の上限を延ばせるかを確かめます（Fluid compute なら延ばせる可能性がある＝要確認）。
  - 延ばせなければ、締め切り（55秒）で打ち切って記録します。費用がかかったかどうかは、OpenAI 側の記録で確かめます。
- **保存場所の容量**：JPEG 1枚は約200〜500KB（推測）。Upstash の無料枠（256MB・1回の要求の大きさの上限は要確認）に収まる見込みです。承認されなかった画像も消さずに残すので、件数を数えて、容量の8割で生成を止めます。
- **商品写真を参考に送ること**：楽天の商品写真を OpenAI に送る（公開はしない）ことが、楽天の規約上問題ないかは【要確認】。

## 6. 守ること（社長の方針との照合）

- 体験したような表現にしない：画像には小さく「AI生成イメージ」と入れ、キャプションにも「画像はイメージです」と書きます。くまが商品を使っている絵が「実際に使った感想」と受け取られないようにするためです。効果・性能を絵で誇張しません（例：光って見える、目が良くなる）。
- 他社のロゴ・商標（服・帽子・家電など）は描かない。客観確認で見つけたら不合格。
- 医療の効果を連想させる場面（目薬をさす・診察する）は、場面の企画で使いません。
- 承認前に外部へ投稿しません。投稿の自動化は、今後も社長の承認が要る段階2で行います。
- 有料APIの呼び出しは、社長が試作を承認するまでしません。

### 段階Bで足すテスト（例）
- マスターが未登録・未承認・ハッシュ値の不一致なら、AIを1回も呼ばず止まる。参考資料のコラージュはマスターとして扱わない。

- 指示文に、キャラクターの固定要素（キャメル色のふわふわ・大きな黒いサングラス・丸い顔・短い手足・3Dの質感）と、場面の企画で決めた衣装と「文字を描かない」が必ず入る。

- 商品写真は楽天の画像サーバーのものだけを使う。
- 客観確認が不合格なら作り直しは1回まで。2回目も不合格なら「画像なし」になる。
- 承認していない画像は、公開の準備（段階2）で使われない。
- 既存の投稿セット・画像を消さない。
