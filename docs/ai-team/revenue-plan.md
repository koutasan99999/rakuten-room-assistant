# 収益目標を中心にした会社の設計（2026-11-16・設計案。まだ実装していない）

最上位の目標：AIを使って、継続的・安定的な利益を生む仕組みを作る。当面は月30,000円の利益（確定報酬 − AI費用などの支出）。
楽天ROOM・Instagramは、今使っている収益化の手段で、会社の目的ではない。
社員の人数・稼働回数・投稿数は評価しない。評価するのは、利益・利益につながる実績・検証で分かったこと。

---

| 知りたいこと | 今の状態 | 出どころ |

いちばん大きい事実：今は「売れたかどうか」を会社の中で確かめる手段が、社長の手入力1つしかない。
そのため、まず数字の入口を作らないと、どの社員の仕事が利益に効いたかを評価できない。

## 3. 評価指標（閲覧から確定報酬まで）

| 段階 | 指標 | 取れるか |
|---|---|---|
| 露出 | Instagramの閲覧・リーチ | 公式APIの鍵があれば自動。なければ社長の手入力 |
| 関心 | 保存・プロフィールアクセス・フォロー | 同上 |
| 流入 | 楽天ROOMへの流入 | 取れない（不明と表示） |
| クリック | 楽天アフィリエイトのクリック数 | 成果レポートの画面にあるか要確認 |
| 購入 | 発生報酬（売上の発生） | 成果レポートの画面・CSV（要確認） |
| 確定 | 確定報酬 | 成果レポートの画面（要確認） |
| 利益 | 確定報酬 − AI費用 − その他の支出 | 確定報酬が入れば計算できる |

決まり：取れない数字は「不明」。推定は「推定」と書き、実績の欄に入れない。
Instagramと楽天の数字は、人単位でつなげられない。同じ時期・同じ商品で並べて見せるだけにし、「この投稿で売れた」と断定しない。

### 売れなかったときの原因の切り分け（数字がそろったときだけ）
- 露出不足：閲覧が少ない → 投稿の時間・表紙・交流を見直す
- 関心不足：閲覧はあるが保存・プロフィールアクセスが少ない → 企画・商品の魅力を見直す
- クリック不足：プロフィールアクセスはあるがクリックが少ない → ROOMへの案内・導線を見直す
- 購入への転換不足：クリックはあるが発生報酬がない → 商品・価格・紹介文を見直す
データが足りない段階は「判断できない（不足している数字：〜）」と表示する。

## 4. 経営ダッシュボード（経営報告のいちばん上に置く）

1. 今月の確定報酬と、30,000円への進捗
2. 今月の発生報酬（確定前。確定報酬とは別の欄）
3. 今月のAI費用（実測）と、損益（確定報酬 − AI費用 − その他の支出）
4. 商品別・企画別の成果（成果レポートの商品名と、投稿セットの商品を照合。照合できたものだけ）
5. Instagramの閲覧・プロフィールアクセス・フォロー
6. 流入・クリック・購入（取れるものだけ。取れないものは「不明」）
7. 社員ごとの業務実績と、成果への貢献（例：その社員が関わった投稿セットのうち、公開されたもの・報酬が出た商品を含むもの。因果は断定しない）
8. 今の詰まり（例：確認待ちの投稿セットが3件あり、公開されていない）

出勤状況は、この下に置く（「何人働いたか」を会社の中心にしない）。

## 5. 15分ごとの仕事の選び方（経営管理＝コード）

1. 詰まりを先に見る：社長の確認待ちの投稿セットが3件以上なら、制作を止める（作っても公開されず、費用だけかかるため。今は6件）。
2. 数字の取り込み（0円）を先にする：公開済みの投稿の数字が古ければ取り込む（鍵があるとき）。
3. 実績のある方向を優先する：報酬が出た商品・保存の多かった企画があれば、そのジャンルをバイヤーAIのテーマの先頭にする。実績がなければ、ジャンルを固定せず広く探す（防災を特別扱いしない）。
4. 予算の配分：1日25円・月1,000円は変えない。目安として、制作12円・バイヤー5円・交流3円・分析と経営企画5円（実測で見直す）。
5. 仕事探しの記録（worker:board）に、「収益目標との関係」を1行で残す（例：「確認待ちが0件のため、公開できる投稿を作る」）。
6. 期待収益の数字は、実績が出るまで出さない（根拠のない予測で順番を決めない）。

## 6. 経営企画AI（新規事業の調査と提案）

- 仕事：今の事業の数字と、新しい収益源の調査をもとに、提案書を作る。今の事業を続けるのが最善なら、その結論でよい。
- 調査の方法と費用：
  - コードが、決めた公式ページ（各サービスの規約・料率・始め方のページなど）を読みに行く。無料。AIはその内容を要約・比較するだけ（1件あたりの見込み：数円）。
  - 検索エンジンでの自由な調査は、OpenAIのWeb検索機能が追加料金のため、使う前に見積もりを出して社長の承認を取る。
  - 承認がなくても、社長が頼めば、開発の場（このClaude）で出典つきの調査報告を作れる。
- 提案書の項目（10項目）：事業の内容／収益の発生の仕方／想定顧客と需要の根拠（出典つき）／初期費用・維持費／社長がする作業／AI社員が自律的にできる作業／収益化までの見込み・根拠・不確実性／競合・規約・法的リスク／小さく試す検証方法／今の事業と比べた優先順位。
- 評価：提案の数ではなく、出典の確かさと、検証して分かったこと。根拠のない案を大量に出さない（月に1〜2件まで）。
- 承認：新規事業の開始・有料契約・外部アカウントの作成・公開・支出は、すべて社長の承認制。

## 8. 今わかっている課題（2026-11-13 の本番の事実）

- 15分ごとの自動実行が、本番で一度も起動していない（GitHubの記録0件）。自律運営の前提なので、最優先で原因を調べる。
- 本物のAIで制作ラインを1件通したが、監査で不合格（修正2回）。不合格の理由を確かめてから、制作の品質を直す。
- 確定報酬・発生報酬の記録がまだない。数字がないうちは、どの仕事が利益に効いたかを評価できない。
