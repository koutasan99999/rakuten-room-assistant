# ROOM商品発掘（rakuten-room-assistant）

楽天市場から商品をランダムに探し、AI（OpenAI）が最大5件を選んで、ROOM用の紹介文まで用意するスマホ向けWebアプリです。

最重要コンセプトは「まず、このアプリの運営者本人が欲しくなる商品を見つける」こと。売れ筋やレビュー数ではなく、新しい発見・小さな不満の解決・値段に対する欲しさで選びます。

使い方：アプリを開く →「商品を発掘する」→ 気になる商品の「楽天で商品を見る」→「紹介文をコピー」→ 楽天ROOMに投稿

## なぜGitHub PagesではなくVercelなのか

GitHub Pagesは「見た目のファイルを置くだけ」の場所なので、APIキーを置くと誰でも見られてしまいます。
Vercel（無料プラン）なら、APIキーをサーバー側の「環境変数」に隠したまま楽天・OpenAIを呼び出せます。
画面もAPIもこのリポジトリ1つから自動で公開されるので、GitHubに変更を入れるだけで更新されます。

## 構成

| 場所 | 役割 |
| --- | --- |
| `index.html` / `css/` / `js/` | スマホ画面 |
| `api/discover.js` | 「商品を発掘する」の処理（Vercel上で動く） |
| `api/curate.js` | 「選び方まとめを作る」の処理 |
| `lib/themes.js` | まとめの型（6種類）とテーマ一覧。テーマごとに検索キーワードと価格帯の枠を持つ |
| `lib/curation.js` | まとめの組み立て（順番・どんな人に・価格差の中身） |
| `lib/rakuten.js` | 楽天市場 商品検索API（2026-07-01版、ページランダム化・除外・重複除去） |
| `lib/ai.js` | OpenAIでの商品選定と紹介文生成（NG表現の除去、失敗時の予備表示） |
| `lib/genres.js` | 32ジャンルと検索キーワード、運営者の好み・反応の良いジャンルを優先する重み付け |
| `test/` | 自動テスト（`npm test`） |

## Vercelに登録する環境変数

| 名前 | 内容 |
| --- | --- |
| `RAKUTEN_APP_ID` | 楽天ウェブサービスのアプリID（applicationId） |
| `RAKUTEN_ACCESS_KEY` | 楽天ウェブサービスのアクセスキー（accessKey） |
| `OPENAI_API_KEY` | OpenAIのAPIキー |
| `APP_PASSCODE` | 合言葉（他人に使われてAPI料金がかからないようにするため） |
| `OPENAI_MODEL`（任意） | 使うモデルを変えたいとき。未設定なら低コストモデルを自動で選びます |
| `RAKUTEN_AFFILIATE_ID`（任意） | 楽天アフィリエイトID |
| `RAKUTEN_REFERER`（任意） | 楽天に送るReferer。未設定ならアプリのURLを自動で使います |

楽天ウェブサービスの管理画面で、アプリの「許可されたWebサイト」にVercelのURL（例：`xxxx.vercel.app`）を登録してください。

## ジャンルの選び方

毎回「ジャンル → そのジャンル内のキーワード → 検索ページ（1〜5）」の順にランダムに選びます。
ジャンル・キーワードは `lib/genres.js` の一覧に1行足すだけで増やせます。

さらに、iPhone側でジャンルごとに次の回数を記録し、反応の良いジャンルを少しずつ優先します（最大3倍まで。反応のないジャンルも選ばれ続けます）。

| 記録 | タイミング | 重み |
| --- | --- | --- |
| shown | そのジャンルの商品が表示された | 分母 |
| clicked | 「楽天で商品を見る」を押した | 1点 |
| copied | 「紹介文をコピー」を押した（ROOM投稿の目安） | 2点 |
| posted | ROOMに投稿した（将来追加予定） | 3点 |

記録はiPhoneの中（ブラウザ）だけに保存され、外部には送られません。
将来「投稿した」ボタンや、成果の出たジャンルの記録を足すときも、同じ仕組みに点数を加えるだけで済みます。

## 商品選定と紹介文のしくみ

1. AIが候補ごとに「欲しい度（1〜10）」を内部評価し、高い順に最大5件。弱い商品は外す（最低3件は表示）
2. AIにはレビュー数を渡さない（売れ筋で選ばせないため）
3. iPhoneに最近表示した商品名を20件まで記録し、同じ商品は候補から除外、似た商品はAIに避けてもらう
4. 生成後に定型表現・推量の多用・運営者目線の選定理由・字数をチェックし、問題のある商品だけ1回書き直し

## 選び方まとめ

「結局どれを買えばいい？」に答えるためのモード。型を選ぶ（またはおまかせ）と、テーマの枠ごとに楽天で価格帯を指定して商品を集め、AIが順番と理由を組み立てます。

| 型 | 中身 |
| --- | --- |
| まず1個買うなら | 迷ったらこれ → もう少し○○したい人の2番手・3番手 |
| 初心者向け | 最初の1個 → 次に足すもの（高機能すぎるものは避ける） |
| 本命＋安い代替 | 定番の本命と、何が似ていて何を妥協するかが分かる安い代替 |
| 予算別 | 低・中・高価格と、高い方は何にお金を払っているか |
| プレゼント | 誰に・予算・関係性に合わせる |
| 用途別 | 同じジャンルを用途ごとに |

各商品には「こんな人に」「この位置の理由」「価格差の中身」「ROOM紹介文」が付き、まとめ全体を1つの文章としてコピーすることもできます。テーマは `lib/themes.js` に足すだけで増やせます。

## 料金を抑える工夫

- AIへは商品名・価格・レビュー・説明を短く切り詰めた情報だけを送ります
- 低コストモデル（nano / mini クラス）を使い、1回の発掘につきAI呼び出しは原則1回です
- 合言葉で自分以外が使えないようにしています
