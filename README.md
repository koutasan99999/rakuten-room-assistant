# ROOM商品発掘（rakuten-room-assistant）

楽天市場から商品を探し、AI（OpenAI）が最大6件を厳選して、ROOM用の紹介文まで用意するスマホ向けWebアプリです。

最重要コンセプトは「まず、このアプリの運営者本人が欲しくなる商品を見つける」こと。売れ筋やレビュー数ではなく、新しい発見・小さな不満の解決・値段に対する欲しさで選びます。

「眼科医くまのInstagram編集部」として、企画 → 商品 → 文章 → Instagram素材までを用意します。

基本の流れ：「今日の企画を考える」→ 3案から1つ選ぶ → 企画の6つの役割で商品を探して厳選 →「採用／今回は外す」で5〜6商品に → 「紹介文をコピーしてROOMに投稿」でROOMへ →「採用した商品でInstagram投稿を作る」で画像とキャプション → 投稿 → 履歴に保存（次の企画で重複を避ける）

## なぜGitHub PagesではなくVercelなのか

GitHub Pagesは「見た目のファイルを置くだけ」の場所なので、APIキーを置くと誰でも見られてしまいます。
Vercel（無料プラン）なら、APIキーをサーバー側の「環境変数」に隠したまま楽天・OpenAIを呼び出せます。
画面もAPIもこのリポジトリ1つから自動で公開されるので、GitHubに変更を入れるだけで更新されます。

## Vercelに登録する環境変数

| 名前 | 内容 |
| --- | --- |
| `RAKUTEN_APP_ID` | 楽天ウェブサービスのアプリID（applicationId） |
| `RAKUTEN_ACCESS_KEY` | 楽天ウェブサービスのアクセスキー（accessKey） |
| `OPENAI_API_KEY` | OpenAIのAPIキー |
| `APP_PASSCODE` | 合言葉（他人に使われてAPI料金がかからないようにするため） |
| `OPENAI_MODEL`（任意） | 使うモデルを変えたいとき。未設定なら低コストモデルを自動で選びます |
| `RAKUTEN_AFFILIATE_ID`（任意） | 楽天アフィリエイトID |
| `RAKUTEN_REFERER`（任意） | 楽天に送るReferer。未設定ならアプリのURLを自動で使います |

楽天ウェブサービスの管理画面で、アプリの「許可されたWebサイト」にVercelのURL（例：`xxxx.vercel.app`）を登録してください。

## 発掘条件

| 指定 | 動き |
| --- | --- |
| すべて空（または「おまかせで発掘」） | 今まで通りの完全ランダム発掘 |
| ジャンルだけ | そのジャンルの検索語で単品発掘 |
| 自由入力あり | AIが「何を・誰向けに・何に使う・予算いくら」を読み取り、検索語と価格帯にしてから単品発掘 |
| 選び方の型あり | 選び方まとめ。ジャンルや自由入力があれば、その条件から枠（検索語・価格帯）を組み立てる。なければ用意済みテーマ |

条件の読み取りに失敗したときは、自由入力から予算（「1万円以下」など）と語句を取り出す簡易ルールで続行します。指定した条件はiPhoneに保存され、次に開いたときも残ります。

## ジャンルの選び方

毎回「ジャンル → そのジャンル内のキーワード → 検索ページ（1〜5）」の順にランダムに選びます。
ジャンル・キーワードは `lib/genres.js` の一覧に1行足すだけで増やせます。

さらに、iPhone側でジャンルごとに次の回数を記録し、反応の良いジャンルを少しずつ優先します（最大3倍まで。反応のないジャンルも選ばれ続けます）。

| 記録 | タイミング | 重み |
| --- | --- | --- |
| shown | そのジャンルの商品が表示された | 分母 |
| clicked | 「楽天で商品を見る」を押した | 1点 |
| copied | 「紹介文をコピー」を押した（ROOM投稿の目安） | 2点 |
| posted | ROOMに投稿した（将来追加予定） | 3点 |

記録はiPhoneの中（ブラウザ）だけに保存され、外部には送られません。
将来「投稿した」ボタンや、成果の出たジャンルの記録を足すときも、同じ仕組みに点数を加えるだけで済みます。

## 商品選定と紹介文のしくみ

1. 楽天から最大40件ほどの候補を集め、AIが候補ごとに「欲しい度（1〜10）」を内部評価して最大6件を厳選。6件には「一番外しにくい」「価格を抑えるなら」などの役割を持たせる。弱い商品は数合わせせず外す（最低3件は表示、6件未満なら「今回は条件に合う商品がN件でした」と表示）
2. 発掘結果は「Instagram用にまとめてコピー」で、役割・商品名・価格・理由を①〜⑥の一覧としてコピーできる
3. AIにはレビュー数を渡さない（売れ筋で選ばせないため）
4. iPhoneに最近表示した商品名を20件まで記録し、同じ商品は候補から除外、似た商品はAIに避けてもらう
5. 生成後に定型表現・推量の多用・運営者目線の選定理由・字数をチェックし、問題のある商品だけ1回書き直し

## 選び方まとめ

「結局どれを買えばいい？」に答えるためのモード。合計6件を目安に（比較中心なら3〜5件）、「本命＋安い代替」は本命3＋代替3のように枠ごとに複数選びます。型を選ぶ（またはおまかせ）と、テーマの枠ごとに楽天で価格帯を指定して商品を集め、AIが順番と理由を組み立てます。

| 型 | 中身 |
| --- | --- |
| まず1個買うなら | 迷ったらこれ → もう少し○○したい人の2番手・3番手 |
| 初心者向け | 最初の1個 → 次に足すもの（高機能すぎるものは避ける） |
| 本命＋安い代替 | 比較軸（ブランド性・価格差・用途・センス感 など）を決め、本命ブランド／手が届く本命／実力派の代替／かなり安い代替／用途違い の5枠から6個。ブランド・価格帯・見た目・用途の重複を避け、各商品に「なぜ本命か／なぜ代替として成立するか」の一言 |
| 予算別 | 低・中・高価格と、高い方は何にお金を払っているか |
| プレゼント | 誰に・予算・関係性に合わせる |
| 用途別 | 同じジャンルを用途ごとに |

各商品には「こんな人に」「この位置の理由」「価格差の中身」「ROOM紹介文」が付き、プレゼント・本命＋安い代替・ブランド系のテーマでは「ブランド・贈り物として」の評価と分類（外しにくい王道／大人向け など）も付きます。まとめ全体を1つの文章としてコピーすることもできます。テーマは `lib/themes.js` に足すだけで増やせます。

### 本命＋安い代替のしくみ

- 候補集め：テーマごとに5枠（本命ブランド・手が届く本命・実力派の代替・かなり安い代替・用途違い/ギフト向き）で、価格帯と検索語を変えて楽天を検索
- AIへ：全候補に「価格帯 高・中・低」を付けて渡し、比較軸・役割・本命/代替・一言（pick）を出させる
- 選んだ後の点検：同じショップは2個まで、ほぼ同じ商品名は1個に間引く。価格差が小さい・本命側か代替側が無いときは画面で知らせる
- 画面：まとめに「比較軸」、各商品に「本命/代替」のタグと「→ ブランド込みで欲しいならこれ」のような一言。Instagram画像の一言メモにもこの一言が反映される

## 今日の企画を考える（編集部）

1. サーバーが企画データベース（`lib/catalog.js`）から「ジャンル × 投稿の型」を3つ選ぶ。3案どうしでかぶらず、直近10投稿で使ったジャンル・型ほど選ばれにくい
2. AIがそれぞれを具体的な企画にする：タイトル（○○について本気出して考えてみた）・投稿の型・ターゲット・価格帯・ジャンル・ブランド・面白い理由・比較軸・6つの役割（それぞれ楽天の検索語と価格帯つき）。直近10投稿（ジャンル・型・ターゲット・価格帯・ブランド）と季節も材料にする。AIが失敗したら簡易的な3案
3. 1つ選ぶと、その6つの役割の枠で楽天を検索し、AIが1枠1商品を厳選（なぜ選ぶか・誰向けか・ブランド・くまの一言メモつき）
4. 商品ごとに「採用」「今回は外す」。採用した商品で「Instagram投稿を作る」→ 表紙・（まとめ）・商品カード・ROOM誘導の画像と、キャプション（なぜこのテーマか・選び方の基準・誰向けか・ROOMへの誘導、最後に `#PR` とアフィリエイト表記を必ず付ける）
5. 投稿履歴（テーマ・使用商品・ブランド・ジャンル・投稿型・日付・投稿済みか）を保存し、次の企画づくりに使う。投稿管理の「投稿履歴」タブで見られる

保存（ZIP）は `generated_posts/日付_テーマ/01_cover.png … 03_item_01.png … 08_room_cta.png / caption.txt`。

| 3 | iPhoneアクセ | まずコレ | まず1個買うなら |
| 4 | 香水初心者 | 初心者向け | 初心者向け |
| 5 | 30代男性へのプレゼント | プレゼント | プレゼント |
| 6 | 1,500円以下で試せる便利グッズ | 価格縛り | まず1個買うなら |
| 7 | 充電器 ― 高い本命と安い代替 ― | 本命＋代替 | 本命＋安い代替 |
| 8 | 自分では買わないけど、もらうと嬉しいもの | プレゼント | プレゼント |

- 商品発掘の画面の「企画から作る」→「この企画で作る」で、企画ごとに決めた6つの役割の枠（例：迷ったらこれ・実用性重視…）で楽天を探し、AIが1枠1商品を選んで「なぜこれを選ぶのか」「誰ならこれを選ぶべきか」を付ける

## 基準ユーザーとブランド信頼度

基準ユーザーは「必要なら多少高くても買える。安さだけでは買わない。ちゃんと選ぶ理由とブランドの信頼を重視する」人。

- 「安いから買う」ではなく「少し高くても、これを選ぶ理由があるから買う」商品を優先
- 低価格品は、明確な機能・独自のデザイン・ブランドが重要でない消耗品や便利グッズ・安さ自体が価値、のときだけ
- 例外の「トレンド枠」：今流行っている・新しい使い方として注目されている商品は、無名・低価格でも積極的に候補に（理由は「安いから」ではなく「今これが流行っているから知る価値がある」。根拠なく流行っているとは書かない）
- 各商品には選んだ根拠（ブランドで選ぶ／デザインで選ぶ／機能で選ぶ／トレンド枠）を表示
- 作り手・販売元を判断材料にするため、全ジャンルでショップ名をAIに渡す

## ブランド・プレゼント適性

プレゼント、ファッション、香水、食器、腕時計、バッグなど、ブランドイメージが判断に影響する商品では、AIに次も評価させます（判断材料としてショップ名も渡します）。

- そのブランドを選ぶ意味、価格の根拠、無名なのに不自然に高くないか、有名ブランドのデザインに似すぎていないか
- 年齢・印象との相性（若すぎる／背伸びしすぎ／ロゴが強い／定番すぎる など）
- 「この人にこのブランドを贈る理由があるか」
- 高価格品と低価格品は「本物と劣化版」ではなく、何にお金を払うか／何を妥協するかで比べる

偽物・コピー品・正規品の断定や「劣化版」という表現は、生成後のチェックで取り除きます。

## 投稿管理（ROOM・Instagram）

各商品カードの下のボタンで、商品ごとに状態を記録できます（もう一度押すと未選択に戻る）。

| 状態 | ボタン |
| --- | --- |
| 未選択 | （何も押していない） |
| ROOM候補 | ROOM候補にする |
| ROOM投稿済み | ROOMに入れた |
| Instagram投稿待ち | Instagram投稿待ち |
| Instagram投稿済み | Instagram投稿済み |

上部の「投稿管理」タブで、状態ごとに一覧できます。「Instagram投稿待ち」では複数の商品にチェックを入れて、まとめてコピー・まとめて投稿済みにできます（「Instagram投稿を作る」は次の段階で、カルーセル投稿の構成・文章の自動生成につなげる予定）。

保存先は今はiPhoneのブラウザ内（無料・設定不要）。別の端末とは共有されません。保存処理は `js/store.js` の `ProductStore`（`getStatus` / `setStatus` / `list` / `counts` / `exportAll`、すべてPromiseを返す）に閉じ込めてあり、データは `{ id, status, name, price, url, image, shop, code, intro, reason, role, createdAt, updatedAt }` の形なので、DBに移すときはこの部品の中身をAPI呼び出しに差し替え、`exportAll` で取り出したデータを移せば済みます。

## Instagram画像づくり

投稿管理の「ROOM投稿済み」「Instagram投稿待ち」で商品にチェック →「Instagram画像を作る」→ 投稿テーマ（例：出産祝い）を入れて「画像を作る」。

- 1080×1350（縦長）で、表紙 →（まとめ）→ 商品カード（1商品1枚）→ ROOM誘導 の順に作る（6商品なら8〜9枚）
- 表紙は「◯◯について 本気出して考えてみた」のシリーズ形式。右下に固定のクマ
- 2枚目（任意）は「まとめ」：型のラベル・見出し・説明・結論をポップなデザインで（クリーム地に水玉、白カード、結論は蛍光ペン風）。選び方まとめの「この内容でInstagram画像を作る」から来るとその文章がそのまま入る。空欄ならAIが商品と役割から作る。文章が長いときは収まるまで自動で文字を小さくする
- 商品カードは、薄いグレーの背景に商品画像を大きく中央配置（周りの余白を切り取り、白い背景は透明にして商品だけを置く。白い商品や写真背景は消さずに角丸で置く）。左上にカテゴリ、右上にページ番号（どちらもグレーの丸ラベル）、中央そろえで短い商品名・補足1行・価格（¥・税込）、左下に固定のクマと吹き出しの「くまの一言メモ」
- 画像はAIに作らせず、決まったテンプレートに流し込むので毎回同じトーンで量産できる。AIは文字（短い商品名・補足・一言メモ）だけを作る（低コストモデルを1回）。一言メモはNG表現・長さ・推量の多さをチェックし、ダメなら選んだ理由から作り直す
- 保存：「写真に保存（まとめて）」でiPhoneの共有シートから写真アプリへ一括保存。「ZIPでまとめてダウンロード」なら `generated_posts/日付_テーマ/01_cover.png …` のフォルダ構成
- テンプレートは `js/ig-render.js` の `TEMPLATES` に関数を足せば増やせる。大きさは `SIZE` で管理（将来の正方形対応用）

## 料金を抑える工夫

- AIへは商品名・価格・ショップ名・説明を短く切り詰めた情報だけを送ります（レビュー数は送りません）
- 低コストモデル（nano / mini クラス）を使い、1回の発掘につきAI呼び出しは原則1回です
- 合言葉で自分以外が使えないようにしています
